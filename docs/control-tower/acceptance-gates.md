# 分阶段验收门禁

任何阶段只有通过对应门禁，才能从 `CODE_READY` 推进到 `INTEGRATED`、`DEPLOYED`、`LIVE_VERIFIED` 或 `BUSINESS_COMPLETE`。

## 1. 通用代码门禁

- [ ] 变更位于独立 Git 分支/worktree，没有混入其他未提交改动。
- [ ] 文档、数据合同和测试与实现同步。
- [ ] `git diff --check` 通过。
- [ ] Python 语法与 Ruff 检查通过。
- [ ] 受影响 pytest 通过；合并前完整测试通过。
- [ ] 前端 TypeScript 检查通过。
- [ ] Vite 生产构建通过。
- [ ] `.env`、凭证、数据库、备份、构建产物和绝对凭证路径未进入 Git。
- [ ] 公开 API 只暴露允许字段，未扩大写权限。
- [ ] REAL/DEGRADED/UNAVAILABLE/DISPUTED 四种状态测试通过。
- [ ] `UNAVAILABLE` 不补零，`DISPUTED` 不平均。

## 2. 历史存储门禁

- [ ] 独立 `control_tower.db`，SQLite WAL 开启。
- [ ] Schema 版本有可重复、幂等的迁移记录。
- [ ] `(site_id,module_id,business_date)` 唯一约束生效。
- [ ] 重跑创建新的 attempt，不覆盖旧 attempt。
- [ ] 并发写入测试不产生重复逻辑运行。
- [ ] JSON 字段大小、枚举和时间格式经过校验。
- [ ] 数据库路径来自配置/环境，不在源码写死生产路径。
- [ ] 单元测试只写临时目录，不触碰生产数据库。

## 3. GSC 模块门禁

- [ ] 工作流模板 `daily_gsc_performance@1.0` 可加载并通过 DAG 校验。
- [ ] 模板只有一个输入节点和至少一个输出节点。
- [ ] 预检、D0 探测、窗口采集、维度采集、确定性分析、持久化、归档、验证按依赖连接。
- [ ] GSC D0 独立探测，D-1 不可用时不向前偷换日期。
- [ ] 返回 D0/D-1、7日/前7日、30日/前30日。
- [ ] 查询、页面、国家、设备维度来自官方 API。
- [ ] 加权位置明确标注，不表述为实测 SERP 排名。
- [ ] `single_source_risk=true` 且注明未经交叉验证。
- [ ] 空查询维度按隐私阈值/低量说明，不生成模拟关键词。
- [ ] 工具失败时返回 `UNAVAILABLE` 信封，不从 demo/mock 路径取数。
- [ ] 结果写入临时历史数据库并可回读。
- [ ] 大型原始响应仅以 Asset Hub `asset_id` 关联。

## 4. 公共只读 API 门禁

- [ ] 未登录 GET/HEAD 可访问明确列入白名单的精确路由。
- [ ] 未登录 POST/PUT/PATCH/DELETE 返回 401/405，不因路径前缀裸奔。
- [ ] 未配置站点返回 404 或安全错误，不泄露站点清单外信息。
- [ ] SQL 使用参数绑定；模块 ID 和站点 ID 使用白名单。
- [ ] 响应不含 token、cookie、secret、内部绝对路径、完整 prompt。
- [ ] 历史范围与行数有上限。
- [ ] 空库返回带原因的 `UNAVAILABLE`，不返回伪造值。

## 5. 工作流/时间规划门禁

- [ ] 创建实例与授权启动分离；未授权实例保持 `PENDING`。
- [ ] Timeline 到点前不触发，到点后只触发一次。
- [ ] 同一站点、模块、业务日期只存在一个逻辑运行。
- [ ] 当天重试折叠显示但保留每次 attempt 证据。
- [ ] Hermes `completed` 不自动映射业务 `DONE`。
- [ ] 节点验收失败时实例为 `BLOCKED`/`FAILED`，Timeline 不 ACK 成功。
- [ ] SEOAgents 内部 APScheduler 保持禁用。
- [ ] 不新增递归创建 Cron 的逻辑。

## 6. 前端中文与详情门禁

- [ ] 用户可见主文案均为简体中文。
- [ ] 官方缩写首次出现时有中文名称。
- [ ] 内部枚举通过词典显示中文，不直接裸露。
- [ ] 卡片摘要的数据日、来源和状态与详情一致。
- [ ] 卡片放大后显示详细维度、历史、证据、建议和执行轨迹。
- [ ] 缺失值显示“数据不可用”，不显示 0、NaN、undefined 或空白。
- [ ] 今日巡检门禁可定位并高亮对应模块卡片；模块状态更新后巡检同步变化。
- [ ] 桌面与移动端布局均通过截图/浏览器测试。
- [ ] 页面整体不产生无边界滚动；详情和列表使用主题化内部滚动条。

## 7. 部署与线上验证门禁

仅在用户明确批准部署后执行：

- [ ] 生产修改前有可回滚备份和 Git 提交。
- [ ] 构建产物来自目标 commit，记录 commit SHA 与 bundle hash。
- [ ] 服务健康检查通过。
- [ ] API 对两个站点分别回读，确认无串站。
- [ ] 线上页面加载目标 bundle，模块和中文文案可见。
- [ ] 真实数据来源、窗口、状态与数据库一致。
- [ ] REAL/DEGRADED/UNAVAILABLE/DISPUTED 线上渲染符合合同。
- [ ] Asset Hub 产物拿到 `asset_id` 并可回读。
- [ ] 需要飞书交付时，在 Asset Hub 入库后发送并回读文档。

## 8. 阶段完成定义

| 状态 | 必须具备 |
|---|---|
| `CODE_READY` | 代码、文档、局部测试通过 |
| `INTEGRATED` | 全量测试、类型检查、构建、安全与合同门禁通过 |
| `DEPLOYED` | 目标 commit 已部署且服务健康 |
| `LIVE_VERIFIED` | 线上 API/UI/站点隔离和数据回读通过 |
| `BUSINESS_COMPLETE` | 验收、资产、报告、消息和副作用全部闭环 |

不得把低一级状态表述成更高一级状态。
