# 中央存储 · 使用说明

## 为什么不能写本地磁盘

各部门 agent 分布在不同 VPS 上。写在本地的文件,换台机器就找不到了;
容器重建更是直接消失。**任何要留存的产出物都必须进中央存储。**

## 怎么用

只有一个工具:`asset_hub`。你不需要知道东西存在哪台机器、哪个桶。

### 存一份资产

```json
{"action": "put",
 "name": "西班牙IPTV竞品分析.md",
 "kind": "report",
 "content": "...正文..."}
```

返回里的 `key` 就是它的地址,形如 `seo/report/2026-08/西班牙IPTV竞品分析.md`。
**把 key 记进你的任务卡或时间线节点**,否则下次找不回来。

`kind` 决定路由到哪个节点,可选:
`report` 报告 · `content` 内容稿 · `image` 图片 · `dataset` 数据集 ·
`backup` 备份 · `skill` 技能 · `misc` 其他

### 取回

```json
{"action": "get", "key": "seo/report/2026-08/西班牙IPTV竞品分析.md"}
```

### 其他

- `{"action": "list", "prefix": "seo/report/"}` 按前缀列出
- `{"action": "exists", "key": "..."}` 判断是否存在
- `{"action": "delete", "key": "..."}` 删除
- `{"action": "health"}` 各节点连通性
- `{"action": "nodes"}` 已注册的存储节点、容量、用途

## 三条纪律

1. **确认某个对象是否写进去了,用 `exists` 不要用 `list`。**
   列表是最终一致的 —— 刚写完的对象可能几秒内列不出来,
   用 list 判断会得出「没写进去」的错误结论。

2. **写失败就是失败,不要退回本地磁盘。**
   工具返回 `data_status: UNAVAILABLE` 时如实上报。
   静默落到本地会造出「以为进了中央存储、实际散在各机器上」的资产,
   比写失败难查十倍。

3. **key 里的部门段自动按本实例所属部门填。**
   跨部门存放要显式传 `dept`,并且想清楚为什么 —— 默认情况下不该发生。

## 命名建议

`name` 会做安全化处理(空格与特殊符号转 `-`),但仍建议:
- 带上日期或版本:`竞品分析-2026W31.md`
- 不要用「最新」「final」这类词,它们三个月后毫无意义
